GRASSROOTS ENGINE MANAGEMENT · FREEDOM FC-03 FIRST

Unsupported is not obsolete.

Thousands of capable standalone ECUs sit in secondhand boxes because their software stopped at Windows XP. AhhPuck gives them modern logging, evidence-based tuning and a safe, repeatable process. Starting with the Freedom FC-03 on a 4A-GE 20V, then the same loop for the rest.

HOW IT SHOULD WORK

One closed loop, from first plug-in to a learned improvement.

This is the flow the app, the workbench and the command-line tools all implement. Every arrow is a file on disk: raw capture, normalized telemetry, proposal, approval record, assessment, ledger entry.

1ConnectUSB / serial, bridge or replay
2IdentifyECU, firmware, channels
3Profile & parametersengine, sensors, purpose, limits
4Baselineimmutable, hashed, repeated
5Proposeone bounded change
6Approvehuman, checklist, no override of criticals
7Testcontrolled run, stop conditions live
8Assessλ error, repeatability, coverage
9 · Learn ledger entry → next proposal is smaller, or stop
Monitor mode covers steps 1–4 and is the first vehicle-capable release.
Engineer mode adds 5 and 8 as reports. Nothing is sent to the ECU.
Optimize mode closes the loop with fuel-only proposals behind every gate.

SETTING THE PARAMETERS

Limits are set before the engine starts, and they are the real ones.

The values below are read from config/tuning-safety-policy.json, the same file the safety gate enforces. They are provisional and must be validated for your engine and sensors, but they are never invented at run time.

  • never learn from a protection fault
  • never combine fuel and ignition changes in one experiment
  • never extrapolate unknown cells without a review flag
  • never let an LLM authorize an ECU write
  • always retain source map, candidate diff and rollback copy
HARD LIMITSpolicy 0.1-provisional
  • Max fuel cell change2.0 %
  • Max ignition cell change1.0 °
  • Max RPM7 800
  • Max coolant105 °C
  • Max intake air temp65 °C
  • Min battery voltage12.0 V
  • Max knock level0.15
  • Min oil pressure under load180 kPa
REQUIRED EVIDENCE
  • original map backup
  • engine profile verified
  • injector data verified
  • fuel pressure verified
  • wideband calibrated
  • ignition offset verified
  • sensor plausibility passed
  • repeatable log evidence

LEARNING FROM EVIDENCE

An improvement only counts when it repeats.

Every iteration compares a baseline, a candidate and a repeat of the candidate. The result goes into an append-only local ledger. Critical reports cannot be reused, and a candidate without a repeat run stays not assessed.

Lambda error by run

tools/telemetry_stats.py

Illustrative numbers from the example captures in tools/examples/. Repeatability is reported separately and must pass on its own.

Quality gate

target 96 %
  • Objective score
  • Safety-pass fraction
  • Map coverage
  • Repeatability
  • Sensor confidence

Evidence-weighted. Missing evidence counts as zero, so a few good dyno pulls or an AI opinion cannot reach the target alone.

Learning ledger

append-only · sqlite
  1. #01baseline capturedclean
  2. #02fuel 11×7 −1.5 %improved · repeated
  3. #03fuel 11×8 −1.5 %not repeatable
  4. #04fuel 11×8 −0.8 %improved · repeated
  5. #05knock event in runaborted · not reusable

When a step fails to repeat, the next proposal is smaller. When protection fires, nothing is learned from that run.

THE GREATER GOAL

One process. Many unsupported ECUs.

The Freedom FC-03 is the proving ground. Once the loop is verified on real vehicle evidence, the same transport, normalized telemetry, safety gates and learning ledger become adapters for other capable ECUs that lost their software, not their value.

RELEASE GATES · FC-03 TRIAL

Nine gates before a single write.

Each gate must pass before the next is considered. No release may claim a safe tune because the dashboard works.

  1. 1Replay and simulated telemetry
  2. 2USB enumeration without ECU commands
  3. 3Read-only ECU identity capture
  4. 4Read-only live monitor and logging
  5. 5Fault injection: disconnect, stale frames, bad sensors, power loss
  6. 6Vehicle validation at idle and light load
  7. 7Controlled load testing with independent instrumentation
  8. 8Human-reviewed proposal generation
  9. 9Only then, a restricted write experiment
