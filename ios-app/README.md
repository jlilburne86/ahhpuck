# AhhPuck iOS app

The native SwiftUI build of the **AhhPuck Mobile Build** design (Claude Design handoff, v1.2: 43 screens, English and Japanese). The design files are in [`design-import/ahhpuck-mobile/`](../design-import/ahhpuck-mobile/). Its `README.md` is the handoff spec: navigation, data contract, tokens, and the behaviour of every screen. The app is built to look exactly like `AhhPuck Mobile Build.dc.html`.

All numbers on screen are the design's demo data, generated by the same formulas as the prototype's logic class (`App/Model/AppModel.swift`). Real telemetry replaces them once the FC-03 transport is verified. The app never writes to the ECU.

## Open and run

```sh
open ios-app/FreedomIOSApp.xcodeproj
```

Pick the **AhhPuck** scheme and an iPhone simulator, then run. The iPhone 16e simulator is 390×844 pt, the same as the design frame, so it is the one to compare against.

Launch arguments (Scheme → Run → Arguments, or `xcrun simctl launch <device> com.ahhpuck.freedom …`):

| Argument | Effect |
|---|---|
| `-screen S06` | Show one design screen on its own (S01–S43) |
| `-skipOnboarding` | Go straight to the tabs |
| `-ja` | Japanese |
| `-afr` | AFR instead of λ |
| `-tuner` | Tuner density |
| `-live` | Animate the demo telemetry (the design's `live` tweak) |
| `-demoClock` | Status bar shows 9:41, as in the design |

## Layout

- `App/Design/` — tokens (the design's oklch colours converted exactly), fonts, and shared components from the design's F00 foundations.
- `App/Model/` — `AppModel` (the prototype's state and demo data), `Router` (tabs, first-run flow, full-screen modals, sheets), `L10n` (the `ahhpuck-i18n.js` catalog and its rules).
- `App/Screens/` — one file per design screen, `S01.swift` … `S43.swift`.
- `App/Resources/ja.lproj/Localizable.strings` — generated from `design-import/ahhpuck-mobile/ahhpuck-i18n.js`. The keys are the English strings, as in the prototype.
- `App/Fonts/` — Barlow Condensed and IBM Plex (Mono, Sans, Sans JP), SIL Open Font License.
- `Sources/FreedomMobileCore/` — the read-only assessment core and its tests (`swift test`).

### Things that look odd but are deliberate

- **Bar heights.** The design's CSS is content-box, so its 50 px status bar with 6 px padding renders 56 pt tall, and its 82 px tab bar with 10 px padding renders 92 pt. The app uses the rendered sizes.
- **Status glyphs.** The prototype loads Plex from Google Fonts in Latin/Greek/Cyrillic subsets, so ✓ ✕ ⌀ ◐ ◷ ↺ ↗ ₂ ≈ λ are drawn by fallback fonts (Menlo, Courier, Times, Zapf Dingbats). `T(…)` in `Fonts.swift` applies the same faces so the glyphs match.
- **The system status bar is hidden.** Each screen draws the design's status bar (time and transport), and tapping the transport opens the connection sheet (S04).

## Checking a screen against the design

```sh
cd design-import/ahhpuck-mobile && python3 -m http.server 8765 &      # serve the design
cd ios-app/scripts
NODE_PATH=$(npm root -g) node render-design.js http://localhost:8765 "AhhPuck Mobile Build.dc.html" ~/ref ""   # render every screen
./screenshot.sh <16e-udid> /tmp/dd S06 /tmp/S06.png                  # build, launch one screen, screenshot
python3 compare.py ~/ref/S06.png /tmp/S06.png /tmp/cmp.png            # design | app | difference
python3 align.py ~/ref/S06.png /tmp/S06.png 20                        # per-band x/y offset in pt
NODE_PATH=$(npm root -g) node design-geometry.js "http://localhost:8765/AhhPuck%20Mobile%20Build.dc.html" S06 3   # exact design boxes
```

The Python scripts need Pillow; the Node scripts need Playwright and use the installed Chrome.

## Safety boundary

The app does not write to the ECU. `MobileExperimentAssessor` owns only the deterministic assessment result, and its `writeAuthorization` is always `never`. The FC-03 serial link is 9600 7E1; the frame layout on S33 is illustrative until the "?DAT" exchange is verified.
